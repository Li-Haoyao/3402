## Learning Experiment

### Hypothesis

Using AI-assisted development together with GitHub collaboration will improve development efficiency and make group work easier to manage.

I believed this because AI tools can help generate code ideas, explain errors, and suggest improvements faster than working completely manually. However, I also believed that AI-generated work still needs to be checked carefully. Therefore, I wanted to test whether combining AI with GitHub branches and pull requests could make development faster while still keeping the project organised.

---

### Experiment Method

Our group compared a more manual development approach with an AI-assisted development approach while using GitHub for version control.

The experiment focused on these steps:

1. Choose a small development task from the group project.
2. First, try to solve or plan the task manually.
3. Then, use AI assistance to help generate ideas, code suggestions, or debugging support.
4. Save the work using GitHub commits.
5. Use branches and pull requests to review changes before merging them into the main project.
6. Discuss whether the AI-assisted method saved time and whether GitHub helped control the quality of the work.

The main things we observed were:

* How long the development task took
* Whether AI helped reduce confusion
* Whether GitHub made changes easier to track
* Whether branches and pull requests reduced the risk of breaking the project
* Whether group members could understand what had changed

---

### Results

The experiment mostly supported the hypothesis.

AI-assisted development helped reduce the time needed to create and improve code. It was especially useful for generating a starting point, explaining errors, and suggesting possible solutions. This made the development process feel faster than working completely manually.

GitHub also improved collaboration because every change could be recorded through commits. Branches allowed us to work on changes without immediately affecting the main version of the project. Pull requests helped the group review changes before merging them, which reduced the chance of mistakes being added to the final project.

The experiment showed that AI and GitHub work well together when used carefully. AI can speed up development, while GitHub provides structure, review, and version control.

---

### Discussion

One important thing I learned is that AI should not replace review and understanding. AI can generate code quickly, but the team still needs to check whether the code fits the project, whether it works correctly, and whether it follows our project requirements.

GitHub helped make this process safer. If AI-generated code was placed directly into the main project without checking, it could create errors or conflicts. However, by using branches and pull requests, the group could test and review the code first.

This made me understand that development efficiency is not only about speed. A fast solution is not useful if it breaks the project or creates confusion for other team members. A better workflow is one that is both fast and controlled.

## Presentation Rehearsal

This week we also rehearsed a draft version of our final presentation. The presentation was not fully finished yet, but rehearsing early helped us identify problems before the final submission.

During the rehearsal, we checked:

* Whether the microphone audio was clear
* Whether the screen recording was readable
* Whether the project demonstration was easy to follow
* Whether each member understood their speaking part
* Whether we could explain our development workflow clearly
* Whether our GitHub and collaboration process could be demonstrated properly

The rehearsal helped us find some areas that still needed improvement. For example, some explanations needed to be more direct, and the project workflow needed to be shown more clearly. We also needed to make sure the demonstration matched the assignment requirements and did not just describe the project in general.

This helped me understand that presentation preparation is not only about making slides. It is also about practising timing, checking technical quality, and making sure the audience can understand the project process.

## Content Insights

This week I learned that AI-assisted development can be useful, but only when it is combined with proper checking and version control. AI can help generate ideas and code quickly, but GitHub is needed to manage the work professionally.

I also learned more about the purpose of branches and pull requests. A branch allows changes to be developed separately from the main project. A pull request allows team members to review and discuss the changes before they are merged. This workflow is useful because it reduces the chance of one person accidentally breaking the main version of the project.

Another important insight was that commits are not just technical records. They are also evidence of contribution. In a group project, GitHub commits can show who worked on what and when the work was completed. This makes teamwork more transparent.

The presentation rehearsal also helped me understand the importance of demonstrating workflow. It is not enough to say that the group used GitHub or AI. We need to show how we used them, why we made those choices, and how they helped the project.

---

## Career/Employability/Learning Insights

As the member responsible for GitHub workflow, I learned that version control is essential for team projects. Even when AI helps generate code quickly, GitHub provides a reliable way to review changes, track development history, and recover previous versions if something goes wrong.

This week also made me think about employability. In real workplaces, developers are expected to use tools such as GitHub, branches, pull requests, and project boards. They also need to communicate clearly with teammates and explain their work. This practical helped me practise those professional skills in a group project setting.

I also learned that AI is useful, but it does not remove the need for personal understanding. If I only copy AI-generated code without understanding it, I may not be able to fix problems later or explain my work during a presentation. Because of this, I should use AI as a learning and support tool, not as a replacement for thinking.

The learning experiment helped me understand my own learning style better. I learn more effectively when I use AI to get a starting point, then test the result myself and record the working version in GitHub. This process helps me learn faster while still keeping control of the project.

The presentation rehearsal also showed me that early practice is important. Rehearsing before everything is perfect helped reveal gaps in our explanation and demonstration. For the final presentation, I need to speak more clearly, keep my part focused, and explain the GitHub workflow in a way that is easy for the audience to understand.

Overall, this week helped me understand that good development is not only about writing code quickly. It is about using a workflow that supports teamwork, review, quality control, and clear communication.
