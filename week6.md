## Content Insights

This week I learned that teamwork tools are important because group projects need more than just communication. A team also needs a place to store code, a place to plan tasks, and a place to record team expectations.

Slack is useful for communication because it keeps group messages in one place. It is better than only using private messages because everyone can see the same information and decisions. This makes the project more transparent and reduces misunderstandings.

GitHub is useful for version control. I learned that making a commit is not only about uploading code. A commit also records what was changed, when it was changed, and who made the change. This is important in a group project because it provides clear evidence of contribution. It also helps the team track progress over time.

Trello or GitHub Projects are useful for planning because they make tasks visible. A project board can show what needs to be done, who is responsible for each task, and what has already been completed. This is more organised than trying to remember all tasks through chat messages.

I also learned that the group agreement is an important part of project setup. It helps the team decide expectations before problems happen. For example, the group should discuss:

* Preferred communication method
* Expected reply time
* Meeting availability
* Task responsibility
* Deadline expectations
* How to handle unfinished work
* Each member’s technical and soft skills

This practical helped me understand that a good group agreement should be specific. For example, writing “good at WordPress” is less useful than explaining whether someone can help with theme customisation, plugin setup, content writing, testing, GitHub, or documentation.

Another important thing I learned is integration between tools. Connecting GitHub and Trello with Slack can make updates easier to notice. For example, when someone makes a GitHub commit, the Slack group can receive a message. This makes progress more visible and helps the team stay updated without needing to check every tool manually.

## Career/Employability/Learning Insights

This week helped me understand that teamwork and professional tools are important employability skills. In many real workplaces, people do not work alone. They use tools such as Slack, GitHub, Trello, Jira, or Microsoft Teams to communicate, plan, and track work. Learning these tools now is useful because they are similar to the tools used in real software and web development teams.

I also realised that GitHub is not only a place to store code. It can also become part of a professional portfolio. A clear commit history can show that I contributed to a project and worked consistently. This is useful for future employment because employers may want to see evidence of practical work, not only grades or written claims.

The LinkedIn connection task also made me think about professional networking. Before this practical, I mainly thought of LinkedIn as a job-search website. Now I understand that it can also be used to build a professional identity and keep connections with classmates and teammates. These connections may be useful later when looking for internships, group projects, or career advice.

This week also made me reflect on what kind of group member I want to be. I think a good group member should reply clearly, complete tasks on time, and tell the team early if there is a problem. In past group work, one common issue was that people waited too long before saying they were stuck. This caused stress close to the deadline. For this group project, I should try to give updates earlier, even if the task is not fully finished yet.

I also learned that planning at the start of a project can save time later. Setting up Slack, GitHub, Trello, LinkedIn connections, and the group agreement may feel like extra work at first, but it creates a stronger foundation for the project. If the team has clear tools and expectations, it should be easier to divide tasks and avoid confusion.

For my own learning process, this week showed me that I need to improve my confidence with collaboration tools. I can use basic GitHub functions, but I still need more practice with commits, repository structure, project boards, and integrations. My plan is to keep using GitHub during the project instead of only using it at the end, because regular practice will make the workflow feel more natural.
